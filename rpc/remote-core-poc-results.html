Remote Captive Core experiment record

05What each test answered

Descriptive names replace the runbook's P1/P2 labels.

Controlled transport gate

Repeatable tail measurement

1,000 ledgers, 14.48 MiB, about 7× compression, 600 ms cadence and an approximately 8 ms emit window.

Purpose: isolate transport behavior and produce a stable p99.

Real Core reference

Production-shaped source path

Real SAC-6000 LedgerCloseMeta XDR from stellar-core apply-load through the metadata pipe.

Purpose: capture Core's actual burst pattern. About 234 smaller chunks per ledger versus 58 in the controlled source.

Controls

Attribution and clock checks

Uncompressed pairs reproduced prior results within 0.1 ms. Reversing the hosts found 37–50 µs of combined clock and direction asymmetry.

Raw TCP isolated the 5 Gbit/s one-flow limit from the 12.5 Gbit/s aggregate NIC.

07Validated & still open

Validated

  • Remote ledger delivery fits the 80 ms PoC budget, including the heaviest recorded ledger shape.
  • Chunk overlap reduced controlled median delivery 1.85× on the same wire.
  • The controlled workload passed the 4 ms gate; the real-Core reference also finished below 4 ms.
  • The client implements the same LedgerStream interface used by RPC v2 ingest.
  • No measured client fell back from a partial live flow to the retention ring in Runs 3–4.

Still outside this PoC

  • Actual integration into stellar-rpc; the repository contains documented wiring, not a merged RPC change.
  • Full RPC ingest p99 and peak RSS with Core removed from the RPC host.
  • Production TLS, authentication, high availability and service ownership.
  • Multi-subscriber scale and recovery beyond the 10,000-ledger retention window.
  • Run 4 caveat: 18 raw compression fallbacks occurred during Core setup; the final Real-Core counter was not captured.
